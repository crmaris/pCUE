# Cooling controllers

Use **Cooling controllers** in the main window with **This PC** selected and the original Commander PRO connection/acquisition closed. The original six-channel PRO bench, fixed-RPM, tachometer, protected acquisition, remote API and CLI workflows retain their existing behavior.

The new panel detects Commander CORE (1B1C:0C1C) and CORE XT (1B1C:0C2A). A single device is selected automatically; multiple devices require a choice. The remembered exact device is never substituted if missing. Select Connect to read its capabilities/RPM. CORE has an EXT/AIO output followed by six fan ports; XT has six fan ports. New outputs stay unchecked. Identify Fan or Pump yourself, choose a minimum and manual whole percentage, then enable only outputs you intend to control. Selecting Pump initializes 100% and a minimum of 60%; these are configurable defaults, not a universal pump specification. No target RPM or wiring-mode change is offered for CORE/XT.

**Experimental:** physical CORE/XT response has not been bench-tested here. Control is offered only when returned firmware data has recognized mode and fixed-percentage types, channel counts and supported selected modes. Unsupported layouts stay monitoring-only. Close competing iCUE/Fan Control utilities first; this panel does not stop services automatically. The protocol briefly enters software mode and returns to hardware mode for each operation, which also changes the controller's global operating state.

Apply atomically saves the original selected mode/power settings before the first write, merges only selected outputs into current tables, and verifies readback. Stop / restore returns captured selected settings while preserving unselected changes and stored curves, then closes the device. Closing the panel restores pending settings first. If feedback or restoration fails, the failed connection is released and recovery stays saved. Reconnect the same physical device and select Stop / restore to reopen its exact saved identity and retry; another controller is never substituted. The panel remains open until recovery succeeds. After an abnormal process exit, reopen the panel and restore before starting another session. Recovery/settings live under `%LOCALAPPDATA%\pCUE\controllers`. Manual percentages remain fixed until changed/restored; this panel does not implement Light's CPU/GPU temperature profiles.

All three applications must adopt the same independently authored MIT-licensed [shared driver and conformance contract](shared/README.md). Light currently uses HidSharp 2.6.4; full pCUE uses its existing 2.1.0. Do not upgrade full pCUE's pinned libraries. The conformance tests cover both versions without real USB. Case Tests adoption is coordinated with its current cooler-automation session; see the handover for current parity.
