# Cooling controllers

Use **Cooling controllers** in the main window with **This PC** selected and the original Commander PRO connection/acquisition closed. The original six-channel PRO bench, fixed-RPM, tachometer, protected acquisition, remote API and CLI workflows retain their existing behavior.

The new panel detects Commander CORE (1B1C:0C1C) and CORE XT (1B1C:0C2A). A single device is selected automatically; multiple devices require a choice. The remembered exact device is never substituted if missing. Select Connect to read its capabilities/RPM. CORE has an EXT/AIO output followed by six fan ports; XT has six fan ports. New outputs stay unchecked. Identify Fan or Pump yourself, choose a minimum and manual whole percentage, then enable only outputs you intend to control. Selecting Pump initializes 100% and a minimum of 60%; these are configurable defaults, not a universal pump specification. No target RPM or wiring-mode change is offered for CORE/XT.

**Experimental:** physical CORE/XT response has not been bench-tested here. Control is offered only when returned firmware data has recognized mode and fixed-percentage types, channel counts and supported selected modes. Unsupported layouts stay monitoring-only. Close competing iCUE/Fan Control utilities first; this panel does not stop services automatically. The protocol briefly enters software mode and returns to hardware mode for each operation, which also changes the controller's global operating state.

Apply atomically saves the original selected mode/power settings before the first write, merges only selected outputs into current tables, and verifies readback. Stop / restore returns captured selected settings while preserving unselected changes and stored curves, then closes the device. Closing the panel restores pending settings first. If feedback or restoration fails, the failed connection is released and recovery stays saved. Reconnect the same physical device and select Stop / restore to reopen its exact saved identity and retry; another controller is never substituted. The panel remains open until recovery succeeds. After an abnormal process exit, reopen the panel and restore before starting another session. Recovery/settings live under `%LOCALAPPDATA%\pCUE\controllers`. Manual percentages remain fixed until changed/restored; this panel does not implement Light's CPU/GPU temperature profiles.

All three applications must adopt the same independently authored MIT-licensed [shared driver and conformance contract](shared/README.md). Light currently uses HidSharp 2.6.4; full pCUE uses its existing 2.1.0. Do not upgrade full pCUE's pinned libraries. The conformance tests cover both versions without real USB. Case Tests adoption is coordinated with its current cooler-automation session; see the handover for current parity.

The panel also detects be quiet IO 373F:0010/MI00. Only commissioned nested model 8003/revision1/firmware wire37 is accepted. The owner's Case Tests investigation verified physical pump/bank response; this full pCUE port has simulated validation only. Release IO Center and its service, wait six seconds, then Connect. It exposes Pump (output1) and one Fan bank (output2), which must both be identified/enabled together. Pump minimum must be at least25%; initial pump role is100%. Keep pump100% during tests/settling/pauses. Bridge and cooler serials bind saved setup/recovery; replacement coolers are never substituted.

IO recovery restores captured bank duty and global mode and deliberately leaves pump100%. Fresh pump/bank/error telemetry is required before normal control. A separate in-process worker holds one-second sessions and attempts full speed on stale feedback, fault or ten-second GUI lease expiry, using the existing exclusive handle. Failed restore blocks closing and retains the saved record. This cannot guarantee fallback after OS hang, USB loss or stuck native I/O cancellation. See shared/README.md for protocol/recovery details.

The panel now also offers **Aquacomputer OCTO** (0C70:F011, eight outputs) and **motherboard headers** actually exposed as IControl by the pinned LHM0.9.4 board/chip mappings. OCTO uses the same shared adapter as Light1.5.0, supports both recognized report layouts, binds path/report serial, restores selected raw mode/power triples, and preserves unrelated current settings without flash writes. Motherboard ports retain exact controller/sensor IDs and reported software ranges; sparse/unavailable headers stay disabled. Stop restores fractional software settings or hands control back to BIOS/default. A readable RPM sensor alone is not a controllable output. Detection tables may differ from Light's pinned0.9.5 and Case's dependency version; do not claim every physical board has been validated.

Motherboard access reuses this application's existing Computer instead of opening/closing a second LHM instance that could disrupt CPU telemetry. Failed IO/mainboard recovery retains its owner and saved record; healthy polling does not re-enable manual writes until Stop / restore succeeds. Keep competing cooling tools closed before taking software control. These ports have local software/adapter validation only; no new physical controller test occurred here.

iCUE LINK framing/topology and percentage commands were researched, but native write control is not enabled: public reference code does not establish an exact previous-state capture/restore contract. No third-party Fan Control application/plugin binary or unlicensed driver source is redistributed. Case's shared CORE/IO/OCTO/mainboard adoption remains in progress; the existing Commander PRO bench workflow is separate.
