# Shared cooling controller contract

The controller sources in this folder are owner-authored, MIT-licensed source. They compile with C# 5 / .NET Framework 4.8 and HidSharp 2.1.0 or 2.6.4. Canonical files live in pCUE-Light `shared/`; consuming applications must carry byte-identical copies and the same CORE/be quiet conformance suites. Keep each application's pinned dependencies. Never port a protocol by treating it as Commander PRO or by changing its six-channel bench arrays. `INativeCoolingController` provides Read/Capture/Apply/Restore and keeps saved recovery compatible across the different UIs.

## be quiet IO

The owner's Case Tests investigation physically verified pump and fan-bank response and restoration on IO bridge 373F:0010/MI00, nested model 8003 revision 1, one MCU, firmware bytes 37 00 00 00 (vendor display 0.0.37). The Light/full ports have software simulations only. No private serials, captures or lab measurements are embedded. Other interfaces, LCD PID 0016, models, revisions or firmware are rejected.

Windows reports are 65 bytes: zero report ID followed by 64 protocol bytes. CRC16 (reflected A001, init FFFF, little-endian trailer) covers the first 62 wire bytes. Requests use exact allocated active bridge/child sessions, nonzero counters, status/echo matching, zero padding and both outer ACK plus routed child reply. Native unbuffered overlapped WriteFile sends each output immediately; owned buffers/events remain allocated until OS completion/cancellation finishes. The input FileStream binds the handle to the runtime completion port, so the write's OVERLAPPED event carries the low-order bit (revision5): its completion must never be queued to that port, which would hand the runtime a request it did not allocate. That final OS cancellation completion can block on a defective driver.

Metadata scans never open unselected devices. A chosen controller verifies its exact bridge path/serial and discovers the nested cooler serial before reading settings. Applications remember the child serial as well as the bridge identity. IO Center and its service must release the interface; wait six seconds for session expiry before connecting. The app refuses a competing vendor process and never stops services itself.

Protocol control index 1 is pump, 2 is one fan bank, 3 is global mode (0 internal/fallback, 1 software). Since software mode affects both, claim the whole pump+bank pair, with explicit Pump/Fan role confirmation. Capture pump/bank duty, mode and child identity; save recovery atomically before writes. Establish pump100, then fan target, then software mode, then a lower commissioned manual pump target if requested. Pump commands default to 25–100%; retain pump100 throughout tests/settling/pauses. Revision4 adds an explicit constructor minimumPumpDuty (0–25) for Case's owner-required manual0–100 range. Light/full retain the existing constructor and default25 floor; this opt-in does not change their pump setup minimums. Physical0–24 response/stop is unverified. The transport bank range is 0–100%; this does not certify physical response over that entire range. Unchanged profile ticks send no repeated setpoints. Revision5: once this owner's verified software-mode pair is established (both previous values supplied and matching the device), a later change writes only the percentage that differs, raising the pump before the bank and lowering it after; the pump100-first sequence remains for the first claim, the emergency park and every update of a stopped (0%) pump. Every normal write checks its current lease immediately before sending and verifies readback; partial cancellation retains recovery.

Read-only samples: channel0 coolant /10 C, 1 pumpRPM, 2 bankRPM, 3 condition/error (not another fan). Each expires after three monotonic seconds. Zero and missing are distinct. PumpRPM >0, bankRPM present, fresh error0 and valid settings are required for normal control. Only explicit minimum0 permits fresh zero pumpRPM after this owner successfully writes and reads back pump0 in software mode. Uncommanded zero, positive-duty zero, missing/stale feedback, wrong mode/settings, failed/partial writes and lease expiry still invalidate control and attempt the full-speed park. Recovery always clears this stopped-pump permission. EOF, identity ambiguity or session errors invalidate feedback. Both sessions have one-second heartbeats. While claimed, expired application lease, stale feedback or a fault latches control off and attempts pump100+bank100+software mode using its existing exclusive handle. Heartbeats continue only after a verified full-speed park. USB/session failure stops that park/heartbeat; physical fallback on expiry has not been universally validated.

The opt-in constructor also accepts an optional Action<string, byte[], DateTime> reportObserver, preserved on exact reconnect, so Case can retain its private raw-report CSV. The callback receives a cloned Windows report, direction IN/OUT and UTC timestamp; modifying it cannot change protocol parsing or writes. Callbacks run on the sending/input threads and must be thread-safe and bounded. An observer failure faults the transport; recovery/evidence must be retained. The default is null. Do not publish raw captures or private identities.

The public Fresh snapshot returns cloned, already-validated BeQuietIoReading samples with their original ReceivedUtc, bridge/child session IDs, raw channel/value and unit. It makes no USB request, refreshes no timestamp and invents no condition0 sample. Stale samples and disposed sessions return empty. Preserve these reception times in Case's footer/CSV/batch adapter rather than reconstructing telemetry from CoreState.

Stop/restore verifies the exact child, restores the captured bank duty and mode, and deliberately leaves pump100 rather than its captured lower value. Stale telemetry does not prevent these known recovery writes. A failed handle may reconnect only the same bridge+child after session expiry. The app must retain recovery/ownership until all writes/readbacks succeed; no explicit SessionClose/ForceStateChange command is implemented. This cooperative safety worker is not an independent external watchdog: another process cannot open MI00 while this owner holds it. A whole OS hang or stuck native I/O cannot be claimed covered.

## CORE / CORE XT

| Property | CORE | CORE XT |
|---|---|---|
| VID:PID | 1B1C:0C1C | 1B1C:0C2A |
| Protocol outputs | EXT/AIO at 0; fans at 1–6 | Fans at 0–5 |
| Identity | SHA256 of kind + normalized exact HID path | Same |
| Control | Fixed whole percentages, 0–100 at driver layer | Same |
| Capture | Selected mask, full hardware modes and fixed percentages | Same |
| Restore | Merge selected captured values into latest full tables; verify | Same |

The app layer requires explicit output opt-in, identifies Fan/Pump by operator choice, validates its permitted minimum and percentage, and saves recovery atomically BEFORE calling Apply. Discovery opens no device and sets no speed. Reads/captures wake the device and return it to hardware mode but send no setpoint writes. Only interface zero and known HID report lengths are accepted. HidSharp Windows report ID is stripped once. Every transaction checks command echo/status, exact count and data type. Firmware endpoint candidates are selected only by returned type tags: modes 03 and percentages 04. Unknown layout, unsupported selected mode, missing motor, rejected write or wrong readback must block control. Unselected settings and stored curves are preserved. No LED data, curve data, wiring modes, software speed defaults or flash-save command is sent.

Use `Read()` for capabilities/telemetry; `Capture(mask)` for baseline; `Apply(desired, previous, writeAllowed)` for selected changes (`-1` means unmanaged); and `Restore(baseline)` for recovery. Supply the current session check to Apply and re-check it before each write. A partial write/cancel keeps the saved baseline. The app must serialize calls and retain recovery until all selected devices restore. `previous` detects another application's changes to managed outputs. The shared global Corsair mutex only coordinates applications that honor it; close competing control utilities. Wake/sleep changes the controller's global operating mode, so concurrent vendor lighting/control software cannot be guaranteed unaffected.

The app MUST enumerate CORE/XT metadata without opening/waking unselected controllers. Poll only the selected exact devices; close deselected handles. Light implements this in Controllers.MayMonitor and Engine discovery/selection, and since 1.5.1 applies the same boundary to OCTO and Commander PRO. Full pCUE waits for the operator to choose Connect. Case Tests must enforce the same boundary before polling. Reading a controller is not equivalent to a passive USB metadata scan.

CORE/XT support is experimental and has simulated protocol verification, not physical validation. liquidctl currently labels this family broken. Do not claim every firmware, actual pump response, sleep/resume, thermal stress or electrical safety has been verified. Commander ST (0C32) is excluded. CORE’s EXT pump is included only when its firmware exposes supported mode and percentage tables. Target RPM, DC/PWM wiring changes and acquisition leases are NOT capabilities of this driver; the original Commander PRO bench workflow retains them separately.

## OCTO and motherboard parity

The shared OCTO adapter independently implements both 1613/1631-byte settings layouts and 263/327-byte telemetry layouts. It binds the exact HID path and learned report serial, validates settings CRC, captures the complete raw report before writes, changes only selected mode/power triples, paces feature operations, checks the live application guard immediately before every transfer, uses bounded readback/retries, and restores selected raw settings into the latest valid report. It never sends the flash-save report. Legacy Light raw-report recovery remains readable. Own-device probes and RPM are exposed; percentage commands do not implement a target-RPM loop.

Motherboard policy uses only actual IControl ports and their reported software range. Capture preserves exact sensor/controller IDs, fractional software settings and the Default/Undefined versus Software distinction. Default/Undefined hands control back to BIOS; it does not reconstruct a different application's external software curve. Writes require the live guard and updated duty readback within two percentage points. Sparse and missing outputs are never substituted. Restore validates every selected identity/range/mode before its first write. Consumers reuse their existing Computer and hardware synchronization: LHM's Ring0 handle is process-global, so a second monitor must not close it underneath CPU telemetry. Full pCUE keeps LHM0.9.4; Light keeps0.9.5. Detection depends on the pinned version's board/chip mappings, with no claim of physical verification on every header. Shared tests cover both OCTO layouts, selected-byte preservation, exact serials, cancellation, ignored writes, fractional/default restoration and partial failures. Full WPF adapter tests cover remembered selection and saved recovery before writes. Case retains its own pump/test/stabilization policies when adopting these adapters.

## iCUE LINK System Hub

| Property | Value |
|---|---|
| VID:PID | 1B1C:0C3F, interface 00 only (interface 01 is a 32-byte notification endpoint) |
| Report | 512 protocol bytes; Windows buffers are 513 with a leading zero report ID |
| Outputs | 14 chain channels; output index i is channel i+1 |
| Identity | SHA256 of kind + normalized exact HID path, plus the chain's `channel=ID` list as ChildSerial |
| Control | Fixed whole percentages 0–100 written to the hub's stored tables |
| Capture | Selected mask, stored modes and stored percentages of the 14 channels |
| Restore | Merge selected captured values into the latest full tables; verify by readback |

`CorsairLink.cs` was written from USB captures of the vendor application and then exercised on one physical hub: firmware property `04 01 90 02`, an iCUE LINK TITAN II chain (fan unit on channel 1, pump head on 13, LCD module on 14). The owner's Case Tests project holds the captures and the full protocol map (`CORSAIR-LINK-PROTOCOL.md`). No private device IDs or captures are embedded here. Other hubs, firmware and chain devices are unverified.

Framing is `[address][01][command][data]` out and `[address][00][command][status][payload]` back, where address 0 is the hub and N reaches the device on channel N. This is NOT Commander CORE framing (which starts `08`), the channel count differs, and a reply buffer is not cleared — always take the payload length from the size query (`09`). Never reuse CORE parsing here.

Measured behaviour that shapes the driver: the hub refuses telemetry and its stored tables while in hardware mode (status 3); entering software mode holds the outputs steady; and after roughly 12–45 s without traffic it drops back to hardware mode by itself. Each transaction is therefore software mode → work → hardware mode under `Global\CorsairLinkReadWriteGuardMutex`, and control is the stored tables (`62 6d` percentage first, then `61 6d` mode 00) so a setting survives the application dying and needs no keep-alive. Stored modes: 00 fixed, 02 curve, 05 nothing on that channel. Only 00 and 02 are accepted as a baseline.

The vendor application must be closed: it keeps the hub in software mode and rewrites setpoints every few seconds. The mutex does not make sharing safe. The app layer must refuse to control a LINK hub while iCUE.exe is running. The chain key changes when devices are re-plugged in a different order; a recovery record taken before that is refused rather than applied to other devices, and must then be undone from the vendor application.

Fan/Pump roles are the operator's explicit choice, as for CORE XT. Device names come from each device's own description (endpoint 40, tag 03) and are informational. **Physically verified on that chain (2026-10-02):** fan channel — 60 % gave 1,235 RPM, 45 % gave 905 RPM, restore returned the stored curve. Pump channel — stored 100 % gave 3,056 RPM, 80 % gave 2,525 RPM, 100 % again 3,054 RPM and held with no traffic at all; restore returned the stored curve (about 2,300 RPM); the fan unit and the LCD module's own speed channel did not move. Case Tests' test mode forced a pump slot given 80 to 100 and left the pump at fixed 100 % on exit. The pump needs about 12 s to climb from 2,300 to 3,050 RPM, so let it settle before judging its speed. Pump values below 80 %, thermal runs, forced USB disconnects and other chains are NOT verified. The public projects listed under Sources describe the same family; this driver was derived from the captures, and no third-party driver source or binary was copied.

## Required parity check

Before releasing, check every source/test in `source-manifest.json` against canonical pCUE-Light and run all three shared conformance suites with the consuming app's dependencies. Record hashes/evidence in the handover. Updating one copy creates a parity gap until the other apps adopt it; report pending apps. Manifest revision5 (BeQuietIoDirect.cs, BeQuietIoController.cs, BeQuietBackendTests.cs) is canonical in pCUE-Light only; full pCUE and Case Tests still carry revision4. Protocol changes belong here first, rather than in separate UI-specific drivers. New peripheral adapters establish Light/full OCTO/mainboard contract parity; complete three-app parity still requires Case adoption and does not certify unknown LINK restoration or every physical board.

Set `shared/* text eol=lf` and the app's conformance-file path `text eol=lf` in `.gitattributes`. These byte hashes include line endings; Windows autocrlf must not change them. `shared/Test-SharedSource.ps1` checks the committed manifest and can compare against a local canonical root.
